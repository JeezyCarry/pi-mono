# 0008 — the security boundary is not the parser

- Status: accepted.
- Context: the deterministic facts in `src/review/request/command-facts.ts` are AST-parsed and were drifting into the role of a release authority — if the parser recognised a shape, the action could be allowed. It cannot carry that weight. A parser proves **structure** (path scope, redirects, pipelines, chains), never **semantics**: it cannot show what `make test` runs, what `./build.sh` does, or what a binary will do. Community practice agrees: both leading agent vendors put the enforcement boundary in the OS, not in command text. Claude Code runs bash under `bubblewrap`/`seatbelt` with filesystem and network isolation and states plainly that a deny rule "matches the command as written", while network enforcement "doesn't depend on the command text"; Codex uses `seatbelt`/`Landlock` sandbox modes. Both use a model only as a review layer on top of that boundary, and ask when a command "can't be fully analyzed".
- Decision: three layers, each with a fixed role.
  1. **Boundary** — the deterministic screen (`src/review/screen/`) is the hard-deny authority, but only for the command shapes it explicitly lists (literal words, a fixed rule set); it is not an OS isolation boundary for arbitrary commands, and no host sandbox is enabled today. Where a host sandbox exists, it would be the real isolation boundary. Nothing the model or the parser says can lift a screen deny.
  2. **Triage** — the AST facts may **escalate** danger and may **prove a bounded scope** for release. They never make a semantic guarantee. A shape they cannot rate is `unproven` and asks, even on a named anchor (`docs/policy.md` Part II, "Release proof").
  3. **Semantics** — the model reads meaning (the four axes, the shared-core claims). It cannot hard-deny (ADR 0006) and cannot release on its own; its `absent` is not an exclusion proof.
- Consequences: AST work stays scoped to structural facts — paths, redirects, pipelines, `/dev/tcp`, fetch-then-execute, unbounded spawn. Questions that are semantic by nature (the body of a task target, the behaviour of an unknown binary) are answered by asking or by a sandbox, never by more parsing. A wrong triage costs an ask, not an allow: `unproven` and the completeness gate are the fail-closed side. If the pi host exposes a sandbox, wiring it raises the ceiling far more than any further parser refinement. Accepting this ADR constrains the design; it is not approval to wire the lanes, which needs its own L3 authorization and a freshly frozen set (ADR 0010).
- Alternatives considered: regex matching (rejected: quoting, command substitution and chains defeat it); AST as the release authority (rejected: `make test` and any unread body are unprovable — the reason `unproven` exists); the model as the boundary (rejected: misreads and prompt injection, and no model verdict may hard-deny); prefix allowlists such as `Bash(git *)` (rejected: a substring rule does not constrain what the command does — Claude Code documents that text-based deny rules are bypassable for exactly this reason).
