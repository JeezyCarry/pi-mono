# 0005 — pi-ai is the classifier lane's representation

- Status: accepted (2026-10-11)
- Context: the classifier lane originally spoke the TypeSafe SDK's shapes (`SystemOneRequest`/`SystemOneResult`/`Questions`, and the SDK's error classes) and reached System One through the SDK's own client. When Pi grew a built-in classifier (`modelRegistry.classify`, pi-ai `ClassifierContext`/`ClassifierResult`), the registry backend became a translation layer between the two shape families. The direct SDK backend existed only to point the lane at an arbitrary System One endpoint from the extension's own config; Pi can host the same endpoints as a registered provider or a custom classifier provider. Keeping both meant carrying a second, redundant representation — and its dependency — for one call path.
- Decision: remove the direct backend and the `@typesafe-ai/sdk` dependency. pi-ai's classifier types are the lane's internal representation end to end: `buildClassifierRequest` returns a `ClassifierContext`, `ClassifierClientLike.classify` returns a `ClassifierResult`, and `projectClassifierAnswers` reads pi-ai's `ClassifierAnswer` (`intent_match` is pi-ai's `bool`, which Pi maps to System One's `noul` on the wire). The lane's failure taxonomy defines its own error shapes (`ClassifierApiError`/`ClassifierTimeoutError`/`ClassifierConnectionError`) instead of the SDK's. A `provider` object is no longer accepted; the loader names the migration (`register the endpoint in pi, then set modelType: "classifier"`).
- Consequences: the lane's endpoint config moves to Pi (provider id + catalog), so the extension holds no endpoint URLs or keys. The audit `rawReply` for defers carries pi-ai's answers, which have no `score.legend`/`probabilities`. Refusals still never fail over: a status decides the failover reason, and refusal wording only the defer kind. `CLASSIFIER_ALIAS_KEY` (`typesafe` as the deprecated threshold-block key) is untouched — it is a separate deprecation that names no transport.
- Alternatives considered: keep the SDK and the direct backend (rejected — a second transport and dependency for a path Pi covers); keep the SDK's shapes as the internal representation while dropping only the client (rejected — the SDK would stay a dependency for types alone, and the registry facade's translation would stay).
